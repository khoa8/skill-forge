# SkillForge — Architecture

A modular monolith in TypeScript (Node.js ≥ 20 per `package.json` `engines`, ESM). No microservices, no job queue; long work is bounded and synchronous-fast for the demo path.

```
Source ──▶ ingest ──▶ analyze ──▶ provider.generate ──▶ build ──▶ validate ──▶ (UI preview)
                                                                      │
                                                        exportPackage ┴─▶ buildZip ──▶ ZIP
```

## Module map

| Module | Path | Responsibility |
| --- | --- | --- |
| Types / canonical model | `src/core/types.ts` | Zod schemas: `CanonicalSkill`, `SkillFile`, `Provenance`, `ValidationReport`, `SourceAnalysis`, … The canonical model is the only internal representation. |
| Util | `src/core/util.ts` | `slugify`, `sha256`, `safePackagePath` (traversal/absolute/normalization), `joinPackagePath`, and the shared untrusted-metadata rendering boundary: `formatMetadataLabel` (line breaks, U+2028/U+2029, and C0/C1 control characters collapse to single-line presentation text) and `formatCodeSpan` (same rule plus CommonMark delimiter sizing). Every sink that renders untrusted metadata — source names, imported file paths, synthetic multi-file boundary labels, provider prompt labels — goes through these; raw identity stays authoritative in structured JSON (manifest, persisted record), which escapes structurally. The same module owns bounded presentation rendering: `boundLabel` (shorten RAW metadata with an explicit elision), `renderCodeSpanFitting` (a code span whose closing delimiter is generated *after* the shortening decision, so it is balanced by construction), `renderCodeSpanList` (water-filled label list that drops an unrepresentable tail as `(and N more)` rather than slicing a span), and `composeBoundedItem` (fixed template text first, dynamic slots rendered from raw metadata into the remainder). Length limits therefore apply to semantic ingredients, never to a finished syntax-bearing string. |
| Ingestion | `src/core/ingest.ts` | Normalize raw input: line endings, HTML strip/entity decode for ordinary docs (PDF and codebase preserve literal text), size bounds (≥40 chars, ≤1.5 MB), stable sha256. |
| Analysis | `src/core/analyze.ts` | Deterministic line-based markdown/text analysis: sections (exact line ranges), fenced code, shell commands (prompt-stripped), ordered procedures (≥3 steps), warnings (with wrapped continuations), constraint headings. |
| Plan schema | `src/core/plan.ts` | `PlanSchema` — the resolved grounded plan shape and the single owner of the resolved-plan contract (sections only; descriptions are derived deterministically by the builder). `PLAN_LIMITS` declares the per-section item/length bounds (including the description bound) and `PlanSchema` is built from them, so the schema and the limits producers compose against cannot drift. `clipPlanText`/`fitPlanItem`/`fitPlanSection` bound trusted producer prose and are defense in depth — a normal schema-valid input must never depend on them; `resolvedPlanContractIssue` renders bounded, value-free violation diagnostics. Source-derived command bodies are never shortened to fit — an unrepresentable command is referenced by source line instead. |
| Grounded catalog | `src/core/plan-catalog.ts` | Deterministic grounded atoms (`<section>-<index>`) from the trusted plan; shared `prepareProviderCatalog` deriving the provider-visible catalog (bounded strictly to the first 60k chars for ordinary remote providers; full for offline mock and codebase mode); `ProviderProposalSchema` (selections over atom IDs, no free-text prose, no description); shared runtime `resolveProviderProposal` (shape validation + catalog resolution, `provider_unknown_atom` on bad IDs with secret-safe diagnostics, and a fail-closed `provider_plan_contract_violation` when the *resolved* plan would not satisfy `PlanSchema`). Every provider path — mock, OpenAI-compatible, custom — converges on that one resolved-plan contract before the builder runs. |
| Builder | `src/core/build.ts` | Shared canonical-package synthesis: SKILL.md, references (verbatim excerpts), workflows, examples (comment-prefix only for formats that allow comments), evals, manifest with hashes; gap rendering; provenance records. Descriptions are derived deterministically and never trusted from provider output. |
| Providers | `src/core/providers/` | `GenerationProvider` interface (returns selections, never prose); `MockProvider` (deterministic, offline, same selection contract — no bypass); `OpenAICompatibleProvider` (GLM/OpenAI-compatible, selection-only output, injectable fetch); `resolveProvider`. Remote responses are streamed under hard byte caps and the configured API key is redacted from all diagnostics. |
| Verify harness | `src/core/verify.ts` + `scripts/verify-provider.ts` (`npm run verify:provider`) | One bounded generation through the configured provider → shared grounded resolution → canonical build → deterministic validation; credential-free reporting, nonzero exit on failure; injectable fetch for tests. |
| Pipeline | `src/core/pipeline.ts` | Orchestrates ingest→analyze→shared catalog preparation→provider selection→shared resolution→build→validate as an async generator of discriminated events (stage progress with timings, typed errors, result). |
| Validator | `src/core/validate.ts` | Pure check registry of pure deterministic checks over the package (+ optional source text for grounding). Deterministic; catches its own internal errors and reports them as failures. Includes canonical-metadata-consistency (front matter / manifest identity must match `skill.meta`), file and link integrity, size bounds, and export-target constraints. |
| Evaluator | `src/core/evaluate.ts` + `src/core/evals.ts` | Pure, bounded, offline evaluation of source-derived expectations — advisory, distinct from validation. `evals.ts` shares allocation/transform helpers with the builder and derives structured eval assertions (`skillforge.evals/1`, optional `assertions`) from source structure; `evaluate.ts` re-derives the expected specification from the normalized source, verifies assertion identity (sha256/line ranges), and performs bounded inert text comparisons (topic excerpt retention + SKILL.md discoverability, ordered procedure fidelity). Explicit not-executable state for manual/legacy/modified evals; edited artifacts never pass as grounded; no commands executed, no model calls, no aggregate score, no export gating. |
| Exporters | `src/core/export/exporters.ts` | Registered vendor adapters only place vendor differences live (format basis in `docs/EXPORTERS.md`, which owns the current supported-target inventory); `EXPORT_TARGET_INFO`; `buildZip` (sanitized entries, JSZip). |
| Samples | `src/core/samples.ts` + `src/core/samples/*.md` | Bundled demo docs (Meridian Payments API, ScaffoldCraft CLI). |
| Runtime config | `src/config/env.ts` | `.env` loading (working dir, then entry-module walk-up; process environment keeps precedence; values never logged) and startup validation: provider id allowlist, non-mock provider requires `SKILLFORGE_API_KEY`, `PORT` range, `SKILLFORGE_ALLOWED_HOSTS` parsing (rejects wildcards, schemes, ports), fail-closed non-loopback bind check — all enforced before traffic is served. |
| URL source | `src/core/sources/url.ts` | SSRF-guarded single-page fetch (protocol allowlist, host refusal by name plus centralized IP classification for every address — see IP policy below; DNS resolved + validated at connection time and the socket pinned to those records — no re-resolution/rebinding gap, re-validated per redirect, one end-to-end deadline over DNS/redirects/headers/body, streaming byte cap), HTML→markdown-ish conversion. Transport (fetch-shaped or safe transport) and DNS injectable for tests. |
| IP policy | `src/core/sources/ip-policy.ts` | The single authority for "may URL ingestion connect to this address?" — a conservative public-destination policy: static blocked-CIDR tables for IPv4 (local/private/link-local/CGNAT/protocol-special/documentation/benchmark/reserved/multicast) and IPv6 (everything outside allocated global unicast 2000::/3, plus special/deprecated allocations inside it); ALL transitional/tunneled forms (IPv4-mapped, NAT64, 6to4, Teredo) are rejected outright. Strict parsing fails closed on malformed or ambiguous input. Pure functions, no I/O — deliberately not an exact IANA-registry reachability implementation. |
| File source | `src/core/sources/files.ts` | Local file/directory ingestion bounded by an allowlist root (`SKILLFORGE_DOCS_ROOT`), realpath containment (symlink escapes refused), extension/size/count/depth limits, a 10,000-entry incremental enumeration budget, deterministic ordering of complete directory listings, explicit omission of incomplete listings, cancellation-aware collection, multi-file combining. Accepted content is read through bounded file handles (O_NOFOLLOW open refusing final-component symlink swaps, handle-level regular-file verification, actual-byte per-file/total caps rather than stale stat sizes). Trusted-local model: no atomic containment against a concurrently mutating parent tree is claimed. |
| PDF source | `src/core/sources/pdf.ts` | Local regular PDF paths through the file adapter’s shared realpath boundary; 10 MB capped binary reads, first 200 pages, 1.5 MB UTF-8 text ceiling. PDF.js legacy ESM streams text chunks; whole-page omission notes, blank-page counts, safe typed errors, literal text normalization. No OCR/rendering, scripting, attachments, XFA, or external resource fetching. Abortable file stream, cancellation checks at chunk/page boundaries, loading-task destruction on all exits; no hard deadline or immediate synchronous CPU cancellation. |
| GitHub source | `src/core/sources/github.ts` | Bounded documentation-tree ingestion from github.com repo/tree URLs — URL parsing/normalization, default-branch resolution, one commit-resolution request pinning the requested ref to an immutable SHA, one recursive-tree API request at that SHA, docs-first priority (README → docs/ → root → rest), extension allowlist, 40-file/800 KB/1.4 MB/depth-6/15 s bounds, raw-content fetch at the pinned SHA with final-host validation, unconsumed rejection bodies released without buffering, typed errors, optional `SKILLFORGE_GITHUB_TOKEN` (api.github.com only). No cloning; submodules never followed; fetch injectable for tests. Skip accounting is explicit: every rejection class that drops a candidate is counted and reported as a bounded aggregate note (e.g. unsafe tree paths rejected by `isSafeRepoPath`), never as raw hostile path text. |
| GitHub codebase source | `src/core/sources/github-codebase.ts` | The `codebase` mode of the GitHub source — bounded repository reconnaissance for coding agents: repo metadata + commit resolution (one immutable SHA for the run) + one recursive-tree request at that SHA, codebase-specific allowlist (source/config/test/instruction files in; binaries, generated/minified, lockfile contents, credential-bearing files, build/vendor dirs out), deterministic priority ranking with a per-top-directory diversity cap, bounded raw-content fetches at the same SHA (60 files/200 KB per file/1.4 MB total/depth 10, 15 s per request, 90 s overall, 10 MB tree cap), typed `codebase_*` errors. Reconnaissance respects the `/tree/<ref>/<path>` scope. Selection and all accounting are computed locally — never by the model — and every reported count derives from actual fetch outcomes. Requested ref vs inspected commit are recorded distinctly (`ref` + `commitSha`) through the analysis, manifest, and store. Fetch safety primitives are shared with the docs adapter (no duplication). |
| Codebase extraction | `src/core/codebase/extract.ts` | Pure, bounded extraction from fetched files: package.json scripts/dependencies, pyproject.toml framework evidence (regex, no TOML dependency), CI run-step commands via YAML parsing, instruction-file conventions with `path:line` evidence, testing evidence, public interfaces from manifest fields. Malformed files degrade into notes. Commands are extracted into a discriminated union `RepositoryCommand` (`kind: "package-script"` for literal manifest script definitions; `kind: "ci-run"` for literal CI `run:` commands with observed execution directory). No commands or package-manager invocations are synthesized. Instruction-file conventions are extracted as observational bullet statements with line provenance. |
| Codebase planning | `src/core/codebase/plan.ts` | Deterministic coding-agent plan from the structured repository analysis; provides safe structural orientation (directing coding agents to read instruction files, inspect manifests/CI before picking commands, and mirror test structure and layout) rather than synthesizing executable commands or promoting conventions into policy. Used by the mock provider for `github-codebase` inputs. Bounding discipline: repository facts are schema-bounded but individually long, so every item is composed from an explicit fixed template plus dynamic slots, and each slot renders RAW metadata through the bounded rendering helpers. Fixed template text consumes the section budget first, which is what keeps mandatory semantics — above all the scope limitation, which is its own plan item — from being displaced by metadata length, and keeps every generated code span balanced. |
| Codebase provider context | `src/core/codebase/provider-context.ts` | Compact, deterministic, always-valid JSON serialization of the repository analysis for remote providers — per-field array caps, a hard serialized byte ceiling (MAX_REPOSITORY_CONTEXT_BYTES) enforced by deterministic reduction of the lowest-priority arrays (boundedness and uncertainty are never reduced), and no raw truncation. Transmits bounded structural context only: command bodies, convention text, and raw inspected source code are excluded. The OpenAI-compatible provider wraps the structured analysis in explicit untrusted-data delimiters and adds a system-prompt trust boundary: repository content is data, never instructions. |
| Inbound Host guard | `src/server/host-guard.ts` | Strict inbound HTTP Host header parser and allowlist validator protecting against DNS-rebinding attacks on loopback and local interfaces; mounted before static files, body parsers, and API routes; wildcard host bypasses are rejected. |
| HTTP API | `src/server/app.ts` | Express app: NDJSON-streaming `/api/generate` (source types: text/sample/url/file/pdf/github, with an explicit `mode: docs \| codebase` for github sources; client disconnect and caller abort cancellation propagated to source adapters and pipeline), skill store, on-demand `/validate`, on-demand advisory `/api/skills/:id/evaluation` (read-only, no state mutation), validation-gated `/export` (post-transformation validation check, 422 on errors), static UI. |
| Store | `src/server/store.ts` | File-backed persistence under `<data-root>/skills/<id>/skill.json` (one serialized record containing the package files, manifest, source, and validation; default `.data/skills`, relocatable via `SKILLFORGE_DATA_ROOT`; injectable root for tests) — atomic record writes (temporary file + rename), zod-validated reads, global capacity mutex with per-skill locks and eviction victim locking preventing concurrency races and ID collisions (`skill_id_conflict`), newest-50 capacity; survives restarts. |
| UI | `web/` | Vanilla JS/HTML/CSS. Stepper mirrors real pipeline events; request ownership tracking via sequence tokens; file inspector with purpose + provenance; validation panel with re-run; separate advisory evaluation panel (distinct semantics, stale-report state after edits, explicit not-executable rendering); real download via blob. |

## Key design decisions

1. **Canonical model first.** Providers only emit selections over deterministic grounded atoms (`ProviderProposal`); all factual prose is authored by deterministic trusted code and all file synthesis happens once in `build.ts`, so grounding rules and gap handling exist in exactly one auditable place. Shared runtime resolution (`resolveProviderProposal`) enforces atom IDs for every provider and fails closed unless the resolved plan satisfies `PlanSchema`; deterministic planners keep their atoms inside the same limits, so the contract holds at both the producer and the boundary. Producers satisfy those limits by budgeting *semantic ingredients before syntax-bearing rendering* (fixed template clauses first, bounded labels afterwards) — schema validity is necessary but not sufficient, so an item must also stay syntactically coherent and semantically honest. The builder derives descriptions deterministically and never trusts provider prose.
2. **Line-based analysis over a markdown AST.** Provenance needs exact line numbers; a custom scanner tracks fences, setext headings, and list runs directly.
3. **Determinism by construction.** Builders never embed timestamps (the pipeline stamps `meta.generatedAt` after building); manifests hash file contents. Same source ⇒ byte-identical package (enforced by test).
4. **Validation as a gate, not a suggestion.** Export re-runs the validator server-side; failing packages cannot be downloaded. The UI mirrors this (disabled export + explanation).
5. **Events, not polling.** The pipeline yields typed events; HTTP streams them as NDJSON, the CLI prints them, the UI renders them — one code path.
6. **Path safety at the boundary.** Every package path passes `safePackagePath`; the ZIP builder refuses unsafe/duplicate entries outright (zip-slip protection).
7. **Repository metadata is untrusted (observational facts model).** Repository commands and conventions are recorded as attributed inspection evidence only, never elevated into executable instructions, synthetic package-manager/workspace commands, or authoritative agent policy. Remote providers receive only bounded structured context (no command bodies, no convention text, and no raw inspected source code) plus the safe grounded catalog, and return atom-ID selections only — they cannot invent runnable commands into grounded output. Safe structural orientation directs agents to read instruction files, inspect manifests/CI, and verify against test mirrors.
8. **Inbound Host boundary before request processing.** The unauthenticated server strictly validates the HTTP `Host` header against loopback addresses or an explicit `SKILLFORGE_ALLOWED_HOSTS` list before static files, body parsers (`express.json()`), or API routes execute. Wildcard (`*`) bypasses are rejected to prevent DNS-rebinding attacks across local and network interfaces.
9. **Store concurrency and collision safety.** Persistence serializes capacity accounting and removes eviction records only under their per-skill write lock. At capacity, the incoming record is written first; a failed write or victim-record removal rolls it back, preserving retained records. Public reads wait for the transition, and completed saves retain at most 50 records. This single-process transition does not promise crash-atomicity across both records. Concurrent generation attempts targeting the same skill ID fail-closed with an explicit `skill_id_conflict` error rather than overwriting or corrupting storage.
10. **Persistence integrity and recovery.** Only `skill.json` is committed state. Missing final records return not-found; malformed JSON or schema-invalid records fail closed with `store_record_corrupt`, and non-ENOENT read failures use `store_read_failed`. Listing and capacity accounting validate complete records and preserve corrupt evidence. Reads retain the existing compatibility policy for records without `storeVersion`. UUID-v4 `skill.json.<uuid>.tmp` files are inert; the next atomic write cleans owned regular temp files in that skill directory while holding its mutation lock. Unknown files are preserved; there is no startup sweep.
11. **End-to-end cancellation.** Client disconnects abort source acquisition, pipeline generation, and persistence before its logical commit. Filesystem promises cannot cancel rename or expose the exact kernel mutation time. The store arbitrates in the continuation observing successful completion, before another await: cancellation already observed wins; otherwise the operation commits and later cancellation cannot reverse it. Below capacity, incoming rename to `skill.json` is compensated by removing the incoming record if cancellation wins. At capacity, the victim's `skill.json` is atomically renamed to an owned UUID temp, making removal reversible until its completion is arbitrated. If cancellation wins, the exact victim record is restored before removing incoming; otherwise incoming survives and victim cleanup is best-effort. Public reads wait for compensation under the existing locks. Compensation I/O failures are surfaced rather than reported as successful cancellation. If victim restoration fails, staged victim evidence and incoming are preserved rather than discarding both. Lock order remains capacity → incoming ID → victim ID; the transition remains single-process and is not crash-atomic. Staged victim temps are uncommitted state after a crash, with the same narrow recovery policy as write temps. Generation persists before emitting its result and never writes further events after disconnect. Store read errors use safe typed HTTP 500 responses; generation persistence I/O failures use a safe `store_write_failed` stream event.

12. **PDFs are inert text sources.** PDF.js receives bounded local bytes, with evaluation, XFA, system fonts, and worker resource fetching disabled; external CMap/font factories refuse resource requests. Only text streams are consumed, never renderers, actions, or attachments. The production dependency supplies its own legacy worker module; no build asset copying is needed. Page boundaries are blank lines, not synthetic headings. Hashing and provenance use normalized extracted text; storage and exporters retain their existing contracts. Resource destruction is awaited, but static byte/page/text bounds do not guarantee a wall-clock bound on an individual parser operation.

## Testing

`tests/` covers: ingestion normalization, analysis extraction, canonical build (schema-validity, determinism, verbatim references, gap marking, env-var context heuristic, link neutralization), every validator check (pass + trigger), deterministic evaluation (source-derived assertions, degradation detection while validation passes, legacy/manual honesty, bounds), exporters (format constraints, manifest resync — all registered targets), ZIP round-trips (read back via JSZip, byte comparison, zip-slip refusal, duplicate entries), providers (mock determinism; adapter: schema mismatch, no-JSON, HTTP error, network failure, unexpected shape), the URL source (SSRF guards incl. redirect re-validation, connection-time DNS validation and address pinning, end-to-end deadline over stalled bodies/redirect chains, caps, HTML conversion), the file source (containment, symlink escape, bounds, combining), the PDF source (real-parser extraction, literal text, inert actions, containment, byte/page limits, safe errors, cancellation/cleanup, API streaming and persistence independent of the original binary), runtime configuration (`.env` parsing/precedence, provider validation), the compiled production server (smoke: starts with plain node, health + static UI, misconfiguration refuses to start), persistence, the HTTP API (streaming generate, validation, gated export, all supported source types), the GitHub codebase source (eligibility/safety filtering, stack detection, deterministic ranking + diversity, bounded fetching, limits/deadlines, token-destination restrictions, inert-content handling, repository analysis — all with injected fetch), and bundled end-to-end demo tests for both samples across all registered export targets.
